## 3. Migration Actions

### 3.1 Upgrade dependencies

```json
{
  "dependencies": {
    "react": "^18.2.0",
    "react-dom": "^18.2.0"
  },
  "devDependencies": {
    "@babel/core": "^7.23.0",
    "@babel/preset-env": "^7.23.0",
    "@babel/preset-react": "^7.22.0",
    "babel-jest": "^29.7.0",
    "jest": "^29.7.0",
    "jest-environment-jsdom": "^29.7.0",
    "@testing-library/react": "^14.0.0",
    "@testing-library/jest-dom": "^6.1.0"
  }
}
```

### 3.2 Refactor `DataFetcher.js`

- Replace class with `function DataFetcher()`
- Replace `componentDidMount` + `XMLHttpRequest` with `useEffect` + `fetch()`
- Add error state and handling
- Use `useState` for `data`, `loading`, `error`

### 3.3 Refactor `UserProfile.js`

- Replace class with `function UserProfile({ user })`
- **Eliminate** `componentWillReceiveProps` entirely — read `user` directly from props (no state copy needed)
- The prop-to-state copy is unnecessary; functional component re-renders on prop change automatically

### 3.4 Create tests

- `src/__tests__/DataFetcher.test.js` — mock `fetch`, assert loading state then data render
- `src/__tests__/UserProfile.test.js` — assert renders with user, renders "Guest" when no user

## 4. Risk Assessment

| Risk | Mitigation |
|---|---|
| `componentWillReceiveProps` throws in React 18 strict mode | Eliminated entirely in refactor |

| Unhandled XHR errors silently fail | `fetch()` refactor adds explicit error state |
| Prop-to-state copy causes stale data | Removed; props read directly |
